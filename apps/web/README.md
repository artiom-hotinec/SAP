# apps/web

Next.js 16 (App Router) + React 19 + Tailwind CSS 4 frontend, structured with Feature-Sliced Design. See `CLAUDE.md` in this folder for conventions.

## Getting started

From the repo root:

```bash
npm run dev:api   # backend on http://localhost:3003 (needs the database: docker compose up -d db)
npm run dev:web   # frontend on http://localhost:3000
```

## Routes

| Route                                              | Access                                                       |
| -------------------------------------------------- | ------------------------------------------------------------ |
| `/` (dashboard)                                    | requires the `access-token` cookie, otherwise → `/sign-in`   |
| `/facilities`                                      | same as `/`; facilities list (search, sort, details, delete) |
| `/patients`, `/providers`, `/devices`, `/settings` | same as `/`; placeholder pages for now                       |
| `/sign-in`                                         | guests only; with the cookie → `/`                           |
| `/ui-kit`                                          | public demo of the UI kit components in `src/shared/ui`      |

The authenticated routes live in the `src/app/(main)` route group and share a layout with the sidebar (`src/widgets/sidebar`). `/sign-in` and `/ui-kit` have no sidebar.

Redirects are done by `src/proxy.ts`, which only checks that the cookie exists. The API validates the token.

## Backend access

The browser calls `/api/*`; `next.config.ts` rewrites it to `${API_URL}/*` (default `http://localhost:3003`). Same-origin requests let the API's httpOnly `access-token` cookie work. Set `API_URL` in `apps/web/.env` or the shell to point elsewhere.

The API client in `src/shared/api/generated.ts` (plain typed request functions, no React Query) is generated by orval. `GET /facilities` temporarily uses a hand-written wrapper (`src/shared/api/facilities.ts`) until the API's OpenAPI schema describes it correctly. React Query hooks live in the FSD entities layer (`src/entities/session`, `statistics`, `user`, `facility`):

```bash
npm run api:download -w web   # fetch schema.yaml from the running API
npm run api:generate -w web   # regenerate generated.ts
```

## Structure

```
src/
  app/        Next routes (thin re-exports), layout, providers
  views/      FSD pages layer: dashboard, patients, facilities, providers, devices, settings, sign-in, ui-kit
  widgets/    sidebar
  features/   auth/sign-in, auth/sign-out, facility/delete
  entities/   session, statistics, user, facility
  shared/     api, config (ROUTES, cookie name), lib (formatDate, useDebouncedValue), ui (UI kit)
  proxy.ts    auth redirects
```
